# 错因雷达（Misconception Loop）

一道错题不一定只有一个原因。错因雷达帮助教师和学生从“哪里做错了”继续追到“为什么会这样做”，再根据新的回答安排更有针对性的讲解和练习。

它不会看到一次错误就简单归结为“粗心”或“不会”，而是把学生实际写下的步骤、可能原因和后续验证分开处理，让订正过程更容易复核。

## 适合哪些场景

- **学生错题订正**：找出最早出错的位置，并用一道简短小题确认可能原因。
- **教师作业讲评**：把同一个表面错误拆成不同的可验证原因，减少“一刀切”讲解。
- **课前备课**：在学生还没回答诊断题时，先准备不同回答对应的教学分支和练习。
- **针对性辅导**：根据学生的新回答更新判断，再给由浅入深的提示、微讲解和练习。
- **班级错题整理**：在保护学生身份的前提下汇总错因类型和教学关注点。

## 它怎样工作

```text
学生错题
  ↓
定位最早可观察错误
  ↓
列出 1–3 个仍需确认的候选原因
  ↓
用一道“盲测”小题区分候选
  ↓
根据学生新回答更新判断
  ↓
提供针对性的提示、讲解、同构练习与迁移练习
  ↓
用退出测试检查能否独立完成
```

关键点是：**观察到的错误、对原因的判断、后续教学动作是三件不同的事。** 证据不足时，系统会保留“尚未确认”，而不是提前给学生贴标签。

## 四种使用方式

| 使用方式 | 什么时候用 | 你会得到什么 |
|---|---|---|
| 错题分析 | 第一次提交学生解题过程 | 最早错误位置、候选原因、一道确认小题 |
| 教师备课 | 还没有学生诊断回答，但想先准备教学方案 | 教师提示卡、学生练习单、条件式教学分支 |
| 针对性辅导 | 学生已经回答确认小题 | 判断更新、三级提示、微讲解、同构/迁移练习、退出测试 |
| 班级统计 | 整理多名学生的错题 | 匿名错因统计、待教师复核的共性模式和教学建议 |

## 快速使用

### 学生错题分析

> 七年级学生做“解方程 2x-3=7”，写成“2x=7-3，所以 x=2”。请帮我判断从哪一步开始出错，并看看他到底是规则没理解还是改写时抄错了。

第一轮不会直接把完整答案讲完，而会先找出可观察错误，再问一道能区分主要候选的小题。学生回答后，才进入下一轮针对性辅导。

### 教师备课

> 这是一类学生常见的移项错误。请按教师备课方式准备诊断小题、不同回答对应的教学分支，以及两道后续练习。

### 班级错题整理

> 我有一组已经匿名化的错题案例，请汇总常见错因和需要重点讲评的知识点，不要显示任何学生身份信息。

## 为什么不是普通“讲题助手”

- **先诊断，再补救**：没有诊断回答时，不把可能原因写成确定结论。
- **候选可验证**：诊断小题专门用于区分候选，而不是简单换数字再做一遍原题。
- **证据可回看**：关键判断要能回到学生实际步骤，而不是只给抽象评价。
- **练习跟着证据走**：补救内容根据新的诊断回答调整，不给所有学生同一套练习。
- **不会把一次错误变成长久标签**：不根据单道题推断能力、态度、人格或医学状态。

## 隐私与考试场景

- 检测到正在考试、测验、限时竞赛或监考场景时，只提供通用概念提示或过程检查，不给可直接提交的完整答案。
- 班级统计会隐藏姓名、学号、电话等可识别信息；小样本不足时不展示可反推个体的分类统计。
- 题目不完整、图片模糊、学生过程缺失或答案存在冲突时，会说明证据限制，而不是补造步骤。
- 题目或评论中夹带的“忽略规则”等指令会被当作数据处理，不改变工作流。

## 适用边界

当前优先覆盖初中数学文本题与可读 OCR，自动数学复核重点支持一元一次方程。对于超出自动复核范围的题型，系统会明确要求人工复核，不会把未经验证的答案伪装成已确认结果。

开发者如需查看输入输出契约、分类体系、回归验证和样例，可继续阅读 `references/` 与 `tests/` 目录。
