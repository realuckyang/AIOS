此前已确认 schema.sql 与线上数据库存在差异:calls 表缺少 completed_at 列。已决定采用增量迁移,不重建数据库,迁移文件统一放在 server/repository/migrations 下。

01 用户
给 calls 表加 completed_at 字段,老数据用 created_at 回填。迁移脚本放在 server/repository 下,schema.sql 也要同步更新。
02 思考过程 展开

schema.sql 可能落后于线上库,先读取真实的表结构再决定迁移语句。回填只应覆盖已结束的调用,pending 和 running 状态的行保持 NULL。

04 Agent
当前 calls 表没有 completed_at 列。我先写迁移脚本,执行后按 created_at 回填已结束的调用,最后核对仍为 NULL 的行。
05 bash · 写入迁移脚本 exit 0
cat > server/repository/migrations/001-completed-at.sql <<'EOF' ALTER TABLE calls ADD COLUMN completed_at INTEGER; UPDATE calls SET completed_at = created_at WHERE status IN ('completed', 'failed', 'cancelled'); EOF
