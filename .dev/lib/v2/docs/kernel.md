# 内核

v2 的出发点是一个判断标准:**内核只保留对应物理现实的东西,约定全部上移到 userland。**

模型的上下文窗口是客观现实,就像物理内存;进程无法用自身的指令超越承载它的资源,所以资源计量和地址翻译必须由系统层提供。除此之外的一切——子 agent、调用关系、压缩策略、记忆、技能、workflow——背后没有任何物理现实,只有约定,因此不进内核。

## 定义

Agent = 一个带 bash 的模型,能自由调用框架 API 扩展自己的能力。

内核的全部构成:

- **两张表**:`chats`(对话)、`items`(消息)
- **一个工具**:`bash`
- **一套 API**:对话 CRUD、消息写入、停止、SSE
- **一条运行规则**:消息到达即运行
- **一个遗忘原语**:上下文起点指针
- **一行状态注入**:每轮告知模型当前 token 水位

配置(模型服务地址、密钥、模型名、提示词)是环境,不是数据,放在库外,不属于内核本体论。

## 本体论

内核只有两个概念:

- **对话(chat)**:身份、运行状态、上下文指针。对应进程。
- **消息(item)**:属于某条对话的一条标准 Responses API item,外层带 `source` 来源。对应进程地址空间里的一页。

两个原语各管一个概念:「消息即运行」作用在对话上,「上下文指针」作用在消息序列上。

没有 calls、parent、origin、compactions。对话之间的关系不是内核数据,是发生过的事实——记录在创建者的 transcript 里。

## 消息即运行

`POST /api/chats/:id/messages` 写入消息并立即返回;若对话空闲,后台自动运行。这是内核唯一的唤醒原语,也是内核异步性的唯一来源:

- 人发消息、agent 派生对话、子对话回传结果、后台脚本通知、定时唤醒——全部是同一个动作:往某条对话发消息。
- 不提供 start、resume 或 background 参数。进程级异步交给 shell 自身(`setsid ... &`、nohup、重定向)。

输入侧来源只有两类:`user`(人)和 `runtime`(对话之间、脚本回传)。对话自身运行产生 `model`(消息、推理、工具调用)和 `tool`(bash 结果)。`source` 无默认值,写入必须显式指定。

## 遗忘

模型无法不吃已经喂给它的东西,所以「执行遗忘」出不了内核。但它蠢到只剩一个指针:

- `chats.context_start_item_id`:input 组装时只取该点之后的 items。
- items 永不因压缩而删除;持久历史是 UI 和审计的真相,只是不再进模型输入。

压缩的其余部分全部是 userland 策略(见 userland.md):感知水位、决定时机、生成摘要、给未来的自己留言,都由模型自己完成,摘要以普通消息或文件的形式存在。

已知空位:模型失手导致 input 超窗时,请求失败且对话失去自救能力。对应操作系统的 OOM killer,可在内核留一个最粗暴的兜底(超长失败时自动前移指针重试一次)。当前先不实现,由人工拨指针恢复。

## 水位注入

内核每轮把当前对话的 token 用量作为状态注入模型输入(类似 /proc)。这是观测机制,不是策略;何时压缩、压多狠,由模型自己判断。

## Bash

模型唯一的工具。文件读写、系统命令、调用框架 API、派生对话、后台任务,全部通过 shell 完成。内核负责:

- 启动 shell 子进程,设置工作目录与超时
- 对话停止时终止进程组(setsid 逃逸的后台进程刻意不在此列,由约定管理)
- 截断过长输出,将退出码与输出返回模型
- 灾难命令兜底(safety):只拦明显毁掉整台机器的命令字面,不是沙箱

## 运行时保证

- 同一对话不并发运行。
- 进程重启后不存在仍在执行的运行,遗留 running 状态恢复为 idle。
- 数据库是最终事实,SSE 只负责增量通知(全局事件 ID、Last-Event-ID 补发、补不齐发 gap)。
- 停止不删除对话、历史或已产生的修改。

## 人机平权

UI 和 agent 使用同一套 API。人类始终能直接改配置和数据库,这是自我修改(userland.md)的逃生通道。

## 依赖方向

```text
API → Service → Repository
Service → Agent → LLM
Service → Event
```

分层与 v1 相同,但 Service 不再包含 calls;runtime 不再包含压缩调度,只做「取指针之后的 items + 注入水位」的算术。
