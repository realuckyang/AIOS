# UI

v2 的 UI 是一个**通用的对话浏览器**。它不假装懂业务——内核不懂「派生关系」,UI 也不声称知道谁是谁的 worker。它只是 API 的一个客户端,和 agent 平级。

v1 的左右分栏(用户对话 / 执行对话面板)建立在内核懂 calls 与 origin 的假设上,随 calls 一起移除。

## 形态

- **扁平对话列表**:所有对话在同一个列表里,显示标题、描述、运行状态、更新时间。不按 origin 筛选——内核里没有 origin。
- **对话视图**:渲染 items 流(user 右侧气泡;model 消息/推理/工具调用左侧;runtime 左侧默认折叠)、流式增量、错误 banner、水位与用量。
- **并排查看**:可同时打开第二条对话只读查看,替代 v1 的执行对话面板。任何对话都能被并排打开,不限于「当前对话派生的」。
- **设置页**:编辑库外配置(模型服务地址、密钥、模型名、提示词)。

## 结构展示靠约定

想按归属分组、过滤 worker,解析的是 `description` 里的约定(如 `worker of chat X`),不是 schema——就像 `ps` 能按名字聚合进程,但内核没有「进程是干活的还是人开的」字段。约定坏了顶多显示得难看。

## 与内核的接口

- 一条 SSE 连接,事件驱动增量更新;`gap` 时全量重拉。
- 发消息用 `source=user`;这是 UI 与 agent 在 API 上唯一的行为差别。
- 新对话先进前端草稿态,发送第一条消息才真正创建。
- 遗忘表现为:指针之前的历史仍然展示(数据库是真相),但标记为「已不在上下文中」。

## 原则

- UI 不持有内核没有的概念。
- 展示可以解析约定,数据永远来自 API。
- 当前规模不引入路由库和全局状态库。
