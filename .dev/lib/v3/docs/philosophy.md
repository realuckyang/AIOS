# 设计哲学

## 一条判断标准

**内核只保留对应物理现实的东西;背后只有约定的,全部上移到 userland。**

模型的上下文窗口是客观现实,就像物理内存;进程无法用自身的指令超越承载它的资源,所以资源计量(水位注入)和地址翻译(上下文指针)必须由系统层提供。进程的生死是客观现实,所以调度(消息即运行)和执行边界(bash)在内核。人类必须始终能观测和干预系统,这在本产品里同样是物理现实级的约束,所以 console 和「人可直接改文件」在内核层得到保证。

除此之外的一切——子 agent、调用关系、压缩策略、记忆、技能、workflow、UI 形态——背后没有物理现实,只有约定。约定不进内核。

## Agent 的定义

Agent = 一个带 bash 的模型,能自由调用框架 API 扩展自己的能力。

内核给模型的三样东西构成完备性闭环:**持久的对话、消息到达即运行、能触达整个世界(bash)和自身内核(API/文件)的执行能力**。agent 的一切状态(对话、提示词、配置、UI)都是数据,而 agent 拥有读写全部数据的通用工具,所以它能扩展自己、复制自己、改写自己——原理上和「程序存在冯诺依曼机的内存里所以能自我修改」是同一件事。

## 与操作系统的对应

这套设计不是类比 OS,而是逐条复刻了 OS 的核心结论:

- **机制/策略分离**:内核给机制(水位注入 + 指针),策略在用户态(何时压缩、压多狠,模型自己定)。
- **微内核**:L4/Mach 把内核削到 IPC、调度、地址空间三样。本内核恰好也是:消息(IPC)、消息即运行(调度)、上下文指针 + 水位(内存管理)。userland 的 watcher、编排对话对应用户态 server。
- **进程表不落盘**:真实内核的 process table 在内存里,重启即空。status 不持久化,不存在「恢复遗留 running」。
- **Everything is a file**:内核状态以文本文件形态暴露(JSONL),cat 即查询,如同 /proc;Plan 9 路线。
- **syscall 不对称**:读 /proc 不陷入内核,写状态必须 syscall。对应:读走文件,写走 API。
- **OOM killer**:用户态管理自己的内存,内核只在死亡边缘留最粗暴的兜底。
- **LSM / seccomp**:内核提供安全钩子,策略由用户态装载。`rm` 的 `--preserve-root` 保护也在 userland 工具里——Unix 内核从不拦 syscall 字面。对应:guard 钩子在内核,灾难命令模式在 `userland/bin/guard`。
- **中断/信号**:内核 raise 事件,用户态自己注册 handler 消费;内核对消费方一无所知,零订阅者照常运转。SSE 即此。
- **tty / 串口 console**:桌面崩了,串口还在——而且串口能敲命令,不是只读的。内核自带一问一答的 CLI。
- **init(PID 1)**:内核起来后拉起 userland,崩溃重启。
- **libc**:syscall 只有一套且难看,人体工学的糖(CLI 包装)在用户态——且由 agent 自产自销。
- **发行版预装桌面**:默认 UI 只是预装的 userland 发行物,可换可改。

## 为什么最小内核第一次经济上成立

理念上 OS 一直想这么设计,现实中的主流 OS 恰恰不是:Linux 是宏内核,Plan 9 输了,微内核在商业上长期失败。原因不是理念错了,而是两个税:

- **性能税**:用户态边界跨越太贵。
- **生态税**:纯净架构要求所有软件按新约定重写,而人类写软件很贵;生态迁移成本杀死了每一个优雅的最小内核。

在本产品的语境里,这两个税恰好都不存在:

1. 性能瓶颈是模型推理,毫秒级的文件读写和本地回环 HTTP 完全不在关键路径上——付得起纯净的性能代价。
2. userland 软件由 agent 按需现写——技能、索引、仪表盘、workflow 都是它几秒钟生成的造物,没有「说服全世界开发者迁移」的问题。历史上杀死 Plan 9 的是移植成本,而 LLM 把移植成本降到约等于零。

所以 AIOS 不是在模仿现实的操作系统,而是在实现那个 OS 学界一直想要、但因为人力太贵从未负担得起的操作系统。**AI 不只是跑在上面的应用——它是让最小内核第一次在经济上成立的那个变量。**

## 两层的演化方向

- **kernel 的演化方向是冻结**:它是 ABI,稳定且无聊,永不为展示或便利需求迁移。
- **userland 的演化方向是生长**:而且是 agent 自己生长。约定坏了顶多显示得难看,内核的真相不受污染。

这个内核的天花板不在能力,在愿意沉淀多少可靠的约定——而这些约定本身(脚本、技能文件、记忆规范、UI)可以被 agent 自己写出来。
