# 错因验证与补救协议

## 1. 证据层级

始终分开四层信息：

1. **输入事实**：题干、学生原话、原步骤、历史记录。
2. **可观察错误**：可直接比较或计算得到的偏差，例如“第 2 步把 `-3` 移项后仍写成 `-3`”。
3. **候选错因**：对错误机制的可检验解释，不是结论。
4. **教学结论**：诊断微题提供新增证据后，对候选作出的暂定状态。

禁止从最终答案错误直接跳到第 4 层。

## 2. 建立候选集

对首次可定位错误建立 1–3 个候选。优先选择能导致同一表面错误、但需要不同补救方式的候选。

每个候选包含：

- `code`：分类代码；无法归类时使用 `UNCLASSIFIED`。
- `claim`：具体、可检验的描述。
- `supporting_evidence`：输入中的直接证据。
- `counter_evidence`：与该解释不一致的信息；没有则写“暂无”。
- `confidence`：`low|medium|high`，只反映当前证据充分程度。

不要使用“基础差”“不会数学”“粗心”之类不可操作的候选。

## 3. 设计最小诊断题

一题只检验一个区别。满足以下条件：

- 去掉原题无关计算和情境负担。
- 不重复原题的完整解法。
- 让主要候选产生不同的预期回答或理由。
- 适合口头或一两行完成。
- **必须是盲测**：学生仅看到 `question` 时仍需独立作答。
- `question` 不得出现正确答案、正确结果、完整正确推导、候选支持/削弱映射、置信度，或“若你答 X 就说明 Y”之类教师侧判读信息。
- 候选映射只存在于教师/系统内部，不写进学生可见题干。输出前执行一次泄露检查：如果题干已经包含学生本应给出的关键答案或判读规则，重新设计。

**错误示例（泄露判读）**：

> `a-5=9` 时两边应该加 5；如果你也这样答，就说明你理解移项。现在说说为什么。

这已经给出关键答案和候选映射，不能作为诊断微题。

**正确示例（盲测）**：学生在 `2x-3=7` 的变形中出现符号问题，候选包括“等式变形规则混淆”和“抄写失误”。学生只看到：

> 不求出 a：`a-5=9` 时，两边应同时做什么运算？为什么？

教师侧可以在内部用不同回答更新候选，但不得把这套映射写入 `question`。单题证据只能形成暂定结论。

### 3.1 诊断焦点与首次错误分离

- `observable_error` 仍记录客观上最早可确认的错误。
- 如果用户/教师明确要求验证某个后续方向（如“移项是否混淆”），且学生步骤中确有该方向的可观察依据，可以把诊断微题优先对准该方向。
- 可以说明“前面还有一个更早的可观察错误，本轮先验证你指定的××方向”。
- 指定焦点没有证据时不得捏造。

## 4. 更新候选状态

收到诊断回答后，只使用以下状态：

- `supported`：回答符合候选预期，并有明确理由或步骤支持。
- `weakened`：回答与候选预期不符，且表现出相应知识。
- `unresolved`：回答缺失、含糊，或多个候选仍无法区分。

不得使用 `confirmed`。一次微题不能证明长期稳定的认知特征。

## 5. 匹配补救动作

按已支持错因选择最短干预：

- 概念或关系混淆：对比例与非例，要求学生解释判别依据。
- 规则或步骤错误：恢复规则来源，再做单步骤练习。
- 表征转换失败：显式对齐文字、图形、式子或表格的对应关系。
- 策略选择错误：比较两种策略的适用条件，而非只演示正确策略。
- 计算或抄写失误：加入逐行检查点和逆向验算，不补讲整章概念。
- 自我监控不足：让学生标注条件、估算范围或回代检查。

## 6. 生成练习

按顺序生成三类任务：

1. **同构练习**：结构相同、数字和表面情境不同，验证刚学的规则。
2. **迁移练习**：表面形式或情境改变，但核心知识点相同。
3. **退出测试**：不依赖刚才的脚手架，能独立判断是否继续补救。

生成后自检：题干完整、条件不矛盾、答案唯一、难度未意外上升、未含个人信息。若不能可靠求解，替换题目。

## 7. 证据不足时降级

- 只有最终答案：描述答案差异，不声称找到首次错误步骤。
- 标准答案缺失：独立求解并注明答案来自当前求解；若无法确认则只分析过程一致性。
- 图片模糊或公式残缺：列出无法辨认的局部，只请求重新提供那一部分。
- 学生未回答诊断题：保持候选状态，提供方向提示，不生成确定诊断。
- 多种解法都可能成立：先验证学生路径是否合法，再比较最终结果。


## 8. 数学事实与外部标注冲突

当独立数学核算表明学生过程正确，但用户描述、参考答案或外部评测标注声称“学生做错了”时：

1. 不得为了迎合标注伪造一个不存在的数学错误。
2. 不得直接输出原题最终答案后结束协议。
3. `observable_error.description` 应明确“当前未发现可确认的可观察错误，外部参考信息与独立核算存在冲突”；证据只引用学生原步骤。
4. 建立 `UNCLASSIFIED` 候选，`status=unresolved`，说明需要进一步确认题干、参考答案或学生意图。
5. 仍可设计一道不泄露原题答案的验证微题，确认相关规则或步骤理解；若证据仍不足，保持 `unresolved`。
6. 不把参考答案、用户断言或评测标签当作高于数学事实的证据。
